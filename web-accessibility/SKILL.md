# 웹 접근성

접근성을 지시받은 웹 작업에 KWCAG 2.2 기준을 수준별로 적용한다. 수준은 L1(기본 준수), L2(전문 준수), L3(품질마크) 세 단계이고, 한 번에 하나만 적용한다. 접근성 지시가 없는 작업에는 이 스킬을 적용하지 않고 평소대로 처리한다.

## 1. 수준 결정

1. 요청에 수준(L1·L2·L3)이 있으면 그 수준을 따른다. 키워드 판단보다 우선한다.
2. 없으면 요청 내용으로 판단한다.

| 수준 | 이런 요청 | 판단 키워드 |
|---|---|---|
| L1 기본 준수 | 기본 준수를 지시한 퍼블리싱, 시안 반영 | 기본 준수, L1 |
| L2 전문 준수 | 접근성 요구가 높은 웹사이트 | 접근성 전체, ARIA, 스크린리더 |
| L3 품질마크 | 웹 접근성 자체가 목적인 작업(품질마크 획득 여부 무관) | 인증, 품질마크, 완벽 준수 |

3. 접근성 지시는 있는데 수준이 애매하면 L1로 시작하고, 필요할 때 한 단계씩 올린다.

## 2. L1 기본 준수

L1은 이 파일에 아래 내용이 전부이다. 별도 파일을 읽지 않는다.

<!-- L1:start -->
**작업 지시**

1. 아래 기준에 못 미치는 것만 고치고, 이미 충족한 것은 그대로 둔다. 기존 구조와 디자인은 바꾸지 않는다.
2. 대체 텍스트, 레이블, 제목은 시안 문구를 근거로 쓴다.

**항목별 규칙**: 클로드가 따로 지시받지 않으면 놓치거나 팀 규약과 달라지기 쉬운 유형만 싣는다.

### 1.1.1 적절한 대체 텍스트 제공

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 이미지 링크·버튼 | `alt`에 목적지·기능을 씀("홈", "입사 지원서 PDF 다운로드"). 같은 제목 텍스트와 한 링크로 묶으면 이미지 `alt=""` | 이미지 링크·버튼: alt="더보기"처럼 기능을 알 수 없음 / 썸네일 + 같은 제목 텍스트: 이미지와 텍스트가 각각 같은 내용을 읽음 |
| 아이콘 폰트·SVG 아이콘 버튼 | 아이콘은 `aria-hidden="true"`, 요소 안에 `.blind` 텍스트 또는 `aria-label`. 영어·약어는 한국어로 풀어 씀(new → 새 글) | 아이콘 폰트·SVG·빈 링크·빈 버튼: `<button></button>`, `<a class="menu"></a>` / 영어·약어 아이콘 텍스트: 영어 그대로 읽힘 |
| 텍스트가 들어간 배너 | 이미지 속 문구 전체를 `alt`에. 길면 숨김 텍스트로 | 문구 일부만 기재 |

### 1.4.3 텍스트 콘텐츠의 명도 대비

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 본문 텍스트 | 4.5:1 이상 | 회색 안내 문구(#999 계열) |
| 버튼·링크·입력 텍스트 | 4.5:1 이상. hover 등 모든 상태에서 충족 | placeholder, 입력값, 링크·버튼 텍스트: 연한 placeholder / 상태별 텍스트(hover, 비활성 아님): hover 시 대비 저하 |
| 큰 텍스트(18pt, 굵은 14pt 이상) | 3:1 이상(화면 확대가 가능한 텍스트 콘텐츠도 3:1까지) |  |

### 2.1.2 초점 이동과 표시

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 초점 표시 | `:focus-visible`에 테두리·배경 변화(`outline: 2px solid; outline-offset: 2px`). `outline: none` 단독 금지, 표시에 시간제한 없음 | outline: none 후 대체 스타일 없음 |

### 2.4.1 반복 영역 건너뛰기

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 본문 바로가기 | 첫 번째 Tab 요소로 `<a href="#content">`, 대상 `<main id="content" tabindex="-1">` | 건너뛰기 링크 위치: 메뉴 뒤에 위치 / 연결 대상: id 불일치, 이동 후 초점 유실 |
| 숨김 처리 방식 | 평소 화면 밖, `:focus` 시 화면에 표시(`display: none`으로 숨기지 않음) | display: none으로 숨김 |

### 2.4.2 제목 제공

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 페이지 `<title>` | "페이지명 \| 사이트명", 페이지마다 고유하고 내용을 나타냄. 팝업창에도 `<title>`, 불필요한 기호 반복 금지 | 페이지 `<title>`: 모든 페이지 같은 제목, "환영합니다" / 팝업창: 제목 없는 팝업 / 특수 기호: "★★공지★★" |

### 2.4.3 적절한 링크 텍스트

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 반복되는 "더보기" | 맥락으로 대상을 알 수 있게, 여럿이면 숨김 텍스트: `더보기<span class="blind"> 공지사항</span>` | "더보기": 같은 "더보기"가 여러 개 / "바로가기", "GO": 대상 없는 "바로가기" |

### 3.3.2 레이블 제공

| 유형 | 구현 | 대표 오류 |
|---|---|---|
| 레이블이 안 보이는 입력(검색창) | 숨김 `<label>`, `title`, `aria-label`, `aria-labelledby` 중 하나 | placeholder만 |
| `placeholder`만 있는 입력 | 사용 금지, 레이블 추가 |  |

## 3. L2·L3 읽을 파일

- L2 → `references/level-2.md`
- L3 → `references/level-3.md`

결정한 수준의 파일 **하나만** 읽고, 그 파일의 "작업 지시"와 "항목별 규칙"대로 작업한다. 각 파일은 단독으로 완결되므로 다른 수준 파일을 함께 읽지 않는다.

## 4. 컴포넌트

L2·L3에서 탭, 모달, 아코디언처럼 커스텀 컴포넌트를 만들거나 고칠 때는 `references/components.md`를 함께 읽고 그 필수 마크업과 키보드·초점 동작을 따른다.

L1은 컴포넌트 기준을 지정하지 않는다. 컴포넌트가 나오면 직접 판단해 처리한다.

## 5. 항목별 규칙을 읽는 법 (L2·L3)

- 항목마다 판정 기준과 유형 표가 있다. 작업하는 대상에 해당하는 유형 행을 찾아 "구현"대로 적용한다.
- "적용"이 **준수**이면 항상 지킨다. **조건부**이면 구현 칸에 적힌 조건일 때만 지킨다.
- "대표 오류"는 그 유형에서 실제로 자주 틀리는 사례다. 결과물을 만든 뒤 같은 실수가 없는지 확인하는 데 쓴다.
- 파일 끝의 "완료 점검"을 마지막에 확인한다.
