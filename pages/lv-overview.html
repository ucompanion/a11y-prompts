실무 체크리스트

개요

실무 체크리스트는 웹접근성 스킬에 등록할 내용을 담은 카테고리입니다. 이 개요는 등록할 내용이 아니라, 무엇을 어떻게 등록할지 정리한 기획용 문서입니다.

수준 선택 기준

스킬의 수준 결정 규칙으로 등록합니다. 접근성을 지시하지 않은 작업에는 접근성 기준이 개입하지 않고, 클로드가 알아서 처리합니다. 기본 준수(L1)는 지시했을 때만 적용하고, 이때는 기준에 못 미치는 것만 고칩니다. 보통의 웹사이트는 필요한 접근성 수준에 따라 L1~L2를 지키고, 웹 접근성 자체가 목적이면 품질마크 획득 여부와 관계없이 L3로 진행합니다. 전문 준수(L2)와 품질마크(L3)의 기준은 그대로입니다.

수준 이런 상황 판단 키워드 노출 범위
L1 기본 준수 (프롬프트용) 기본 준수를 지시한 퍼블리싱, 시안 반영 기본 준수, L1 규칙 + 구현
L2 전문 준수 (프롬프트용) 접근성 요구가 높은 보통의 웹사이트 접근성 전체, ARIA, 스크린리더 규칙 + 구현 + 판정 + 컴포넌트
L3 품질마크 (프롬프트용) 웹 접근성 자체가 목적인 작업(품질마크 획득 여부 무관) 인증, 품질마크, 완벽 준수 L2 전체 + 엄격 판정 + 놓치기 쉬운 영역

접근성 지시는 있는데 수준이 애매할 때는 낮은 수준으로 시작하고, 필요할 때 한 단계씩 올립니다.

수준 간 관계

세 수준(L1~L3) 페이지는 같은 포맷(적용 기준 → 작업 지시 → 항목별 규칙 → 완료 점검)을 쓰고, 수준이 올라갈수록 다루는 내용이 늘어납니다. 각 페이지는 단독으로 완결되므로 한 번에 하나만 불러옵니다.

  • L2와 L3의 차이: L2는 기존 구조를 유지한 채 현실적으로 지킬 수 있는 범위만 적용하고, 품질마크에서만 문제 되는 세부는 "생략"·"해당 시"로 넘깁니다. L3은 33개 항목에 예외가 없고, 필요하면 구조·디자인까지 바꿉니다.
  • 인증 절차(신청, 심사 단계 등)는 실무 작업이 아니므로 L3에 넣지 않았습니다.

L1 스킬 반영 기준

L1 페이지는 전체 기준으로 그대로 두고, 스킬에는 클로드가 지시 없이도 하는 일을 뺀 나머지만 싣습니다. 기본 동작과 겹치는 내용을 매번 읽게 하면 사용량만 늘고 결과 차이가 거의 없기 때문입니다. L1 페이지 표의 유형 칸에 data-skill 표시가 있는 행이 스킬 반영 대상이며, 변환 스크립트가 이 표시로 걸러냅니다.

분류 스킬 반영 해당 유형
A. 기본 동작과 겹침제외. 기준으로서 L1 페이지에만 둠2.1.1, 3.1.1, 4.1.1, 4.2.1 전체, 1.1.1의 정보·장식 이미지와 <input type="image">, 2.4.2 헤딩 구조, 2.4.3 이미지 링크, 3.3.2 텍스트 입력
B. 팀 규약 고정포함. 답이 여러 개라 규약이 필요한 유형1.1.1 아이콘 버튼, 2.4.1 건너뛰기 구조·숨김 방식, 2.4.2 페이지 <title> 형식, 2.4.3 "더보기"
C. 자주 틀리는 부분포함. 시안에서 읽을 수 없거나 스타일 초기화 중 놓치는 유형1.1.1 이미지 링크·배너, 1.4.3 명도 대비 수치, 2.1.2 초점 표시, 3.3.2 검색창·placeholder만 있는 입력

스킬의 L1 작업 지시는 이 페이지의 작업 지시를 줄여 씁니다. 기준에 못 미치는 것만 고치고 이미 충족한 것은 그대로 두며, 구조·디자인을 바꾸지 않고 시안 문구를 근거로 쓰는 원칙만 남깁니다. 결과 형식이나 보고 방식을 정하는 통제 지시는 읽는 비용이 더 커서 싣지 않습니다.

등록 방식

  • L2·L3는 수준 파일을 하나만 읽습니다. L1은 SKILL.md에 내장되어 파일을 읽지 않습니다. 요청에 수준이 명시되면 그 수준을 우선합니다. 접근성 지시가 없으면 스킬은 아무것도 얹지 않습니다.
  • 컴포넌트별 체크리스트는 L2부터 반영하며, 탭·모달 같은 커스텀 컴포넌트가 있을 때 읽습니다. L1은 이 기준을 지정하지 않으며 클로드가 알아서 처리합니다.

스킬의 동작 순서와 요청 예시는 웹접근성 스킬 가이드(기획용 참고 자료)를 참고합니다.
