결론

접근성 지시 없이 웹사이트를 만들 때 Claude의 기본 처리는 L1에 못 미치거나 L1 일부만 충족하는 수준입니다. 시맨틱 마크업처럼 "좋은 HTML 습관"에 포함된 것은 대체로 처리하지만, 접근성만을 위한 장치는 대부분 빠집니다.

구분 내용
판단 방식 접근성 기준을 따로 적용하지 않고, 일반적인 웹 개발 관행을 따름
잘 되는 것 시맨틱 태그, 페이지 제목, 헤딩, 이미지 alt, <button>·<label> 사용
빠지는 것 건너뛰기 링크, 초점 관리, 상태 속성, 오류 연결, 정지 기능, 숨김 텍스트
일관성 낮음. 요청 문구, 디자인 비중, 코드 길이에 따라 같은 작업도 결과가 달라짐

이 문서는 Claude가 스스로 관찰한 일반적인 경향을 정리한 것으로, 보장된 동작이 아닙니다. 실제 결과는 세션마다 다를 수 있습니다.

항목별 기본 처리

표기: 대부분 거의 매번 처리 · 가끔 상황에 따라 처리 · 드묾 거의 처리하지 않음. 오른쪽 열은 해당 결과가 어느 수준까지 충족하는지입니다.

항목 기본 처리 실제 모습 충족 수준
1.1.1 대체 텍스트 대부분 alt는 넣지만 "메인 이미지"처럼 일반적인 문구가 많음. 장식 이미지 alt=""는 가끔 L1 일부
1.2.1 자막 드묾 영상 태그에 <track>을 넣지 않음 미충족
1.3.1 표의 구성 가끔 <th>는 쓰지만 scope·<caption>은 자주 빠짐 L2 일부
1.3.2 선형구조 대부분 레이아웃을 DOM 순서대로 짜는 편. CSS로 순서를 바꾸는 경우는 고려 안 함 L2 일부
1.3.3 명확한 지시 대부분 문구 자체를 모양·색 지시로 쓰는 일이 드묾 L2
1.4.1 색 무관 인식 가끔 활성 메뉴·오류 상태를 색만으로 표시하는 경우가 많음 미충족~L2 일부
1.4.2 자동 재생 금지 대부분 배경 영상은 muted로 넣음 L2
1.4.3 명도 대비 가끔 본문은 대체로 충족, 보조 문구·placeholder에 연회색을 자주 씀 L1 일부
1.4.4 콘텐츠 구분 대부분 카드·섹션을 여백·테두리로 구분하는 디자인 관행 L3 수준 우연 충족
2.1.1 키보드 사용 대부분 동작은 <button> 사용. 다만 카드 전체 클릭을 div로 만드는 경우가 있음 L1 일부
2.1.2 초점 표시 가끔 커스텀 버튼·입력 스타일에서 outline: none을 넣고 대체 스타일을 빼는 경우가 있음 미충족~L1
2.1.3 조작 가능 가끔 버튼은 넉넉하지만 아이콘 버튼·닫기 버튼이 작아지는 경우가 있음 L2 일부
2.1.4 문자 단축키 해당 없음 단축키를 거의 만들지 않음 —
2.2.1 응답시간 조절 드묾 시간 제한 기능을 만들 때 연장 수단을 넣지 않음 미충족
2.2.2 정지 기능 드묾 자동 슬라이드에 이전·다음은 넣지만 정지 버튼은 거의 없음 미충족
2.3.1 깜빡임 제한 대부분 깜빡임 효과를 거의 쓰지 않음 L2
2.4.1 건너뛰기 드묾 본문 바로가기 링크를 넣지 않음 미충족
2.4.2 제목 제공 대부분 <title>, h1~h3 사용. 헤딩 단계 건너뛰기가 가끔 있음 L1
2.4.3 링크 텍스트 가끔 "더보기" "자세히"를 반복해 쓰고 숨김 텍스트로 보완하지 않음 미충족~L1 일부
2.4.4 참조 위치 해당 없음 — —
2.5.1 단일 포인터 가끔 슬라이드에 버튼은 넣는 편 L2 일부
2.5.2 포인터 취소 대부분 click 이벤트를 기본으로 사용 L2
2.5.3 레이블과 네임 가끔 아이콘 버튼에 aria-label은 넣지만, 보이는 텍스트가 있는 버튼에도 다른 aria-label을 넣는 경우가 있음 L2 일부
2.5.4 동작기반 작동 해당 없음 — —
3.1.1 기본 언어 가끔 <html lang>은 넣지만 한국어 콘텐츠에 lang="en"을 두는 경우가 있음 L1 일부
3.2.1 사용자 요구 실행 가끔 target="_blank" 링크에 새 창 안내를 넣지 않음 미충족~L2 일부
3.2.2 도움 정보 대부분 공통 헤더·푸터 구조라 결과적으로 위치가 일관 L3 수준 우연 충족
3.3.1 오류 정정 드묾 오류 문구는 보여주지만 aria-describedby·aria-invalid 연결과 초점 이동이 빠짐 미충족
3.3.2 레이블 가끔 일반 폼은 <label> 사용, 검색창·뉴스레터 입력은 placeholder만 쓰는 경우가 많음 L1 일부
3.3.3 접근 가능한 인증 대부분 붙여넣기 차단·캡차를 만들지 않음 L2
3.3.4 반복 입력 가끔 autocomplete 속성을 빠뜨리는 경우가 많음 미충족~L2 일부
4.1.1 마크업 오류 대부분 문법 오류는 드물지만 반복 컴포넌트에서 id 중복이 생길 수 있음 L1
4.2.1 웹 애플리케이션 가끔 아코디언 aria-expanded는 가끔, 모달의 초점 이동·Esc·초점 복귀는 대부분 빠짐 미충족~L2 일부

자주 생기는 문제

기본 처리 결과를 L1 핵심 항목에 대 보면, 10개 중 아래 6개가 자주 빠지거나 어긋납니다.

L1 항목 기본 처리에서 생기는 문제 영향
2.4.1 건너뛰기 본문 바로가기 링크 누락 키보드·스크린리더 사용자가 매 페이지 메뉴를 다 지나야 함
2.1.2 초점 표시 디자인을 다듬으며 outline: none만 넣음 키보드 사용자가 현재 위치를 알 수 없음
3.3.2 레이블 검색창·간단한 입력에 placeholder만 사용 입력 중 안내가 사라지고 스크린리더가 이름을 못 읽음
2.4.3 링크 텍스트 "더보기"를 대상 구분 없이 반복 링크 목록에서 목적지를 구분할 수 없음
1.4.3 명도 대비 보조 문구에 연회색(#999 계열) 사용 저시력 사용자가 읽기 어려움
3.1.1 기본 언어 한국어 페이지에 lang="en" 스크린리더가 영어 발음으로 읽음

특히 디자인 완성도를 요구받을수록 커스텀 스타일이 늘어나 초점 표시와 대비 문제가 더 자주 생깁니다.

일관되게 만드는 방법

지시가 없을 때도 원하는 수준이 적용되려면, 기본값을 Claude의 판단에 맡기지 말고 미리 고정해 둬야 합니다.

방법 효과 적용 범위
스킬로 등록(L1~L3 + 수준 선택 규칙) 퍼블리싱 작업마다 자동으로 수준을 판단해 해당 자료만 불러옴 모든 세션
사용자 설정에 한 줄 추가 예: "웹 제작 시 접근성 지시가 없으면 L1 기본 준수를 적용" 모든 세션, 상세 기준은 없음
프로젝트 지식에 실무 체크리스트 업로드 해당 프로젝트 대화에서 자료를 참고 프로젝트 안
요청에 수준 명시 예: "L2로 퍼블리싱해줘" 그 요청만

가장 확실한 조합은 스킬 등록 + 사용자 설정 한 줄입니다. 스킬이 상세 기준을, 사용자 설정이 기본값을 담당합니다.
