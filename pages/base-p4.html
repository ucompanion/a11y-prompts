원칙 4. 견고성

스크린리더 같은 보조기술이 마크업을 정확히 해석할 수 있어야 합니다.

지침 검사항목 퍼블리싱 규칙
4.1 문법 준수 4.1.1 마크업 오류 방지 태그 열고 닫기, 중첩 관계, 중복 id, 중복 속성 오류가 없어야 함
4.2 웹 애플리케이션 접근성 4.2.1 웹 애플리케이션 접근성 준수 커스텀 컴포넌트는 역할(role), 이름, 상태(aria-expanded 등)를 보조기술에 전달

ARIA 사용 원칙:

  1. 네이티브 HTML 요소로 되면 ARIA를 쓰지 않습니다. <div role="button">보다 <button>이 우선입니다.
  2. 네이티브 요소의 의미를 바꾸지 않습니다. <h2 role="tab">처럼 쓰지 않습니다.
  3. 인터랙티브 ARIA 요소는 키보드로 조작 가능해야 합니다.
  4. 초점을 받는 요소에 aria-hidden="true"나 role="presentation"을 쓰지 않습니다.
  5. 인터랙티브 요소에는 접근 가능한 이름이 있어야 합니다.
  6. 상태가 바뀌면 aria-expanded, aria-selected, aria-checked 값을 스크립트로 함께 갱신합니다.
